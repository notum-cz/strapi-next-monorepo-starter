01Strapi basics

Strapi is the content management system (CMS) behind the {{PROJECT_NAME}} website. Everything an editor changes in Strapi is published to the website automatically. No developer and no deployment are needed.

Key terms

TermWhat it means
Content ManagerThe main area in the left sidebar where all content is edited.
Collection typeA list of many entries of the same kind, for example Page or Redirect.
Single typeExactly one entry for the whole site, for example Navbar, Footer, Hierarchy.
EntryOne item in a collection, for example one page or one redirect.
Section / componentA building block of a page (hero, FAQ, features list…). Pages are made by stacking sections.
Dynamic zoneThe Content field on a page where sections are added, reordered and removed.
Draft / PublishedPages and redirects have two states. Save stores a draft that visitors cannot see. Publish makes it live.
Media LibraryCentral storage for images, videos and files. Every image used on the site lives here.
SlugThe URL part of an entry, for example about-us in /about-us.
Full pathThe complete URL of an entry, generated by the system from slugs. Never edit it by hand.
LocaleLanguage version. The site runs in {{LOCALES}}. Switch the locale in the top right of the edit view. Each language version is edited and published separately.

Save vs. Publish

Edit→Save (draft, invisible)→Preview (optional)→Publish (live on the website)
  • Save keeps your changes as a draft. The published version on the website stays unchanged.
  • Publish pushes the current draft live. The website refreshes the affected pages automatically within moments.
  • Unpublish removes the entry from the website but keeps it in Strapi. Use it instead of deleting when you might need the content again.
  • An entry can show Modified: it is published, but there are saved changes that are not live yet. Click Publish again to push them.
Navbar, Footer and SEO Configuration have no draft state.Pressing Save on them changes the live website immediately.

03How to create a new page

  1. Open Content Manager → Page and click + Create new entry.
  2. Fill in Title. It is the page name in Strapi and the default label in breadcrumbs.
  3. Fill in Slug: lowercase letters, numbers and hyphens only, no slash at the start or end. Example: our-services.
  4. Choose the Parent page. A top-level page (/our-services) has the Home page as its parent. A sub-page (/about/team) has About as its parent. The parent defines both the URL and the breadcrumbs.
  5. Optional: Breadcrumb title, a shorter label for breadcrumbs when the title is long.
  6. In Content, click Add a component to content and add sections (chapter 4 and 7).
  7. Fill in the SEO block (chapter 5). At least the meta title and meta description.
  8. Click Save, then Open preview to check the draft on the real website design.
  9. Click Publish. The page goes live at its URL right away.
  10. Link to it where needed: in the Navbar, Footer, or a button on another page (chapter 11).

Changing the slug or parent of a page that is already liveThe URL does not change immediately. You have to run Update hierarchy (chapter 6), which moves the page and creates a redirect from the old URL.

04Building a page with sections

The Content field is a stack of sections. The website renders them in the same order, top to bottom.

  • Add: click Add a component to content at the bottom, choose the category (Sections, Forms or Utilities) and the component.
  • Reorder: drag the handle on a section, or use the up/down arrows.
  • Collapse / expand: click the section header. Collapsed sections show their first text field as a label.
  • Delete: the trash icon on the section header.
  • Duplicate: the duplicate icon on the section header copies the section including its content.

Typical page structures

Landing pageHero → Image With CTA Button → Features List → Carousel → CTA Banner

One H1 per pageUse exactly one main heading (H1) per page, usually in the first section, and H2 for section headings below it. Headings in rich text fields are chosen in the editor's heading dropdown.

05SEO settings

Every page has an SEO block. It controls how the page appears in Google and when shared on social media.

FieldMeaning and recommendation
Meta titleTitle shown in Google and in the browser tab. Max 60 characters. Empty = page Title.
Meta descriptionSnippet text in Google results. Max 160 characters. Write a one-sentence summary with the main keyword.
Meta imageDefault image for social sharing. Recommended 1200 × 630 px.
Meta robotsall (default) lets Google index the page. Use noindex,follow for pages that should not appear in search results (thank-you pages, internal pages).
Og / TwitterOptional overrides for Facebook/LinkedIn (Open Graph) and X previews. Empty = values above are used.
Structured dataJSON-LD for rich results. Developer field, leave empty unless agreed with Notum.

Site-wide defaults (site name for social previews, robots rules) are in SEO Configuration. Change them only after agreeing with Notum.

06Changing a URL: Update hierarchy

When you change the slug or parent of a page that is already published, the URL does not change straight away. The old URL keeps working until you confirm the change in the Hierarchy tool. This protects you from broken links and lost search rankings.

  1. Change the Slug (or Parent) of the page and Publish it.
  2. Open Content Manager → Hierarchy. It lists every pending URL change: old path, new path, and the redirect that will be created. Child pages of a moved page are included automatically.
  3. Click Update hierarchy, review the list in the dialog and confirm. Changes are grouped by language.
  4. The system updates the URLs, creates a Redirect from each old URL to the new one, and refreshes the website.
  5. Check the new URL and that the old URL redirects.
Good practice
  • Change one page at a time: rename, update hierarchy, verify, then the next one.
  • Prefer low-traffic hours for larger moves.
  • Several renames before updating (a → b → c) collapse into one redirect (a → c). Renaming back before updating cancels the change.
  • Redirect chains and loops are cleaned up automatically. Every old URL always reaches the current one in one step.

New pages do not need this: they go live at their URL on first publish.

Never delete auto-created redirects in productionThey keep old links and Google rankings working.

09Media Library: images and files

The Media Library in the left sidebar stores every image, video and file used on the website. A file is uploaded once and can then be picked in any page or section.

Upload files

  1. Open Media Library and the folder the file belongs to.
  2. Click Add new assets.
  3. Drag files into the dialog, click Browse files, or switch to From URL and paste a link to the file.
  4. Optional: click the pencil on a file to fill in its details before uploading (below).
  5. Click Upload assets to the library.

You can also upload directly from a page: in any image field click + and then Add more assets. The file lands in the Media Library as well.

File details

Click a file in the Media Library to open its details.

File nameName in the Media Library. Use a short, descriptive name, e.g. team-office-prague.jpg. It is also part of the file's web address.
Alternative textDescription of the image for screen readers and Google. Used wherever the image has no own Alt text. Always fill it in unless the image is purely decorative.
CaptionShort description of the file. Also used as the image description when the section has no Alt text.
LocationFolder of the file. Change it to move the file.

The details view also has buttons to download the file, copy its link, replace it and delete it.

Replace a file

To update an image everywhere it is used (e.g. a new team photo or logo), open it and click Replace media. Every page that uses it shows the new file, with no need to edit the pages. Then re-publish the pages that use it so the website refreshes them.

Folders

  • Click Add new folder to create one, for example per page or topic (Home, Team, Logos).
  • To move files, select them with the checkbox and click Move.
  • Folders only help editors find files. They do not change the files' web addresses.

Find a file

Use the search field (by file name), Filters (type, date, size) and the sort menu. Switch between grid and list view in the top right.

Delete a file

Check where a file is used before deleting itDeleting is permanent. Pages that still use the file show an empty space instead. Replace the file in those pages first, or use Replace media instead of deleting.

Recommended formats and sizes

TypeRecommendation
PhotosJPG or WebP, about 2× the displayed size, max ~2400 px wide for full-width images. The site creates smaller versions for phones and tablets automatically.
Logos and iconsSVG, or PNG with a transparent background.
Social sharing image1200 × 630 px, JPG or PNG.
DocumentsPDF.
Size limit250 MB per file. Keep images well under 1 MB: large images slow the website down.
Before uploadingCrop and resize images on your computer first, and give the file a meaningful name. Strapi cannot crop to a fixed ratio, and renaming later does not change the file's web address.

12Redirects

Redirects send visitors from an old URL to a new one. They are in Content Manager → Redirect.

  • Redirects for renamed or moved pages are created automatically by Update hierarchy (chapter 6).
  • For anything else, e.g. an old marketing URL, create one by hand:
  1. Redirect → + Create new entry.
  2. Source *: the old path including the language prefix, e.g. /en/old-page.
  3. Destination *: the new path on the same site, e.g. /en/new-page.
  4. Publish. It takes effect within about 2 minutes.

Each language needs its own redirect. Only published redirects are active. Unpublish or delete one to stop it. Redirects are temporary (HTTP 307) by design, so a wrong one can be fixed without visitors' browsers remembering it.

13Form submissions

Messages from the Contact Form and sign-ups from the Newsletter form are stored in Content Manager → Subscriber. Each entry shows the name, email and message the visitor sent.

  • Entries are read-only records. Do not edit them.
  • Delete an entry when the person asks for their data to be removed.
  • To export the list, ask Notum.

14Preview, publishing and cache

Preview

Pages have an Open preview button in the edit view. It shows the saved draft in the real website design, so you can check everything before publishing. Switch between Draft and Published to compare. Save first, preview shows only saved changes.

A never-published page gets its preview after the first Save.

When do changes appear?

ChangeVisible on the website
Publish / unpublish a pageWithin moments (the site refreshes affected pages automatically).
Save Navbar / FooterWithin moments.
Publish a redirectWithin about 2 minutes.
Slug or parent changeOnly after Update hierarchy.

If a change does not show after a few minutes, reload the page with Cmd/Ctrl + Shift + R. If it still does not show, contact Notum with the page URL and the time of publishing.

15Checklists and troubleshooting

Before publishing a page

  • Slug is lowercase with hyphens, Parent is set.
  • Exactly one H1 on the page, section headings are H2.
  • Every image has an Alt text.
  • Internal links use type page and have New tab turned off.
  • Linked pages are published.
  • SEO meta title (≤ 60 chars) and meta description (≤ 160 chars) are filled in.
  • Every language version is filled in and published.
  • Checked in Preview on desktop and mobile width.

Troubleshooting

ProblemCause and fix
New page shows 404The page is not published, or its Parent is wrong. Check the parent (Home for top-level pages) and publish.
Renamed page still at old URLRun Hierarchy → Update hierarchy.
Page missing in another languageEach language version is published separately. Switch the locale and publish it.
Button does not workLink type page points to an unpublished page. Publish the target page.
Image missing on the websiteThe file was deleted from the Media Library. Upload it again and pick it in the section.
Old image still shows after Replace mediaRe-publish the pages that use it, then reload with Cmd/Ctrl + Shift + R.
Redirect does nothingIt is not published, or the source path lacks the language prefix. Wait about 2 minutes after publishing.
Cannot save, field highlighted redA required field is empty or the format is wrong (e.g. slug with capitals, URL without https://).
SupportFor anything not covered here, contact the Notum team with the page URL, what you changed and a screenshot.
